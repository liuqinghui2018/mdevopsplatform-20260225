### 2.1 主数据现状调研与主数据识别

#### 2.1.1 工作内容与交付物

**主要工作内容：**

1. 现状摸底访谈：对 15+ 源头系统及各业务域（研发、采购、生产、质量、销售、财务、售后等）开展访谈，梳理现有主数据管理现状与痛点
2. 集成关系分析：绘制系统间数据流向图，识别主数据的产生源（Golden Record Source）与消费方
3. 主数据识别与分类：依据 4R 原则（Reusable / Referenced / Regulated / Refined）识别 42 类主数据对象，明确主数据范围
4. 模板梳理：收集各系统现有主数据字段及格式，形成 AS-IS 字段对照表
5. 报告需求调研：收集各业务域的数据质量问题清单及数据需求，确定质量基线
6. 现状差距分析：对标 MDM 成熟度模型，输出现状评估与改进建议

**关键交付物：**

- 主数据现状评估报告（含集成关系图、数据流向图）
- 主数据识别清单（42 类主数据对象目录）
- AS-IS 字段对照表（各系统主数据字段映射）
- 数据质量现状基线报告

### 2.2 主数据标准与方案设计

5. 主数据标准规范评审：组织多轮业务评审，确认标准一致性

- 主数据管理蓝图文档
- 主数据模型设计规范（42 类实体 ER 图）

### 2.4 主数据采集清洗

#### 2.4.1 工作内容与交付物

**主要工作内容：**

1. 历史数据剖析：对各系统历史主数据进行数据剖析（完整性、唯一性、一致性、规范性分析），识别脏数据清单
2. 数据清洗规则制定：制定物料描述标准化、供应商名称归一化、重复物料去重、空值补全等清洗规则

4. 数据标准化转换：建立历史编码与新标准编码的映射表（Cross-Reference），完成编码转换
5. 数据加载验证：验证加载后数据的完整性和准确性，输出数据质量提升报告

**关键交付物：**

- 历史数据质量分析报告
- 数据清洗规则手册
- ETL 开发规范与程序文档
- 数据迁移方案与迁移验证报告

### 2.6 系统分发集成与上线测试

#### 2.6.1 工作内容与交付物

**主要工作内容：**

1. 集成架构设计：设计 MDM → ESB/API 网关 → 15+ 下游系统的分发架构，制定实时/准实时/批量三种集成模式
2. 接口开发与调试：开发 100+ 条 MDM 向下游系统分发的接口，含报文格式对接、错误重试机制
3. 集成测试（SIT）：执行系统集成测试，验证 100+ 条接口的功能正确性和数据一致性
4. 用户验收测试（UAT）：组织各业务域关键用户开展 UAT 测试，确认业务场景覆盖
5. 性能与压力测试：验证高峰期接口响应时间（实时接口 SLA ≤ 3 秒）
6. 上线切换：制定灰度切换方案，按系统逐步切换（非全量一次切换），并提供上线应急预案

**关键交付物：**

- 集成架构设计文档
- 接口规范文档（100+ 条接口清单、报文格式、错误码）
- SIT 测试报告
- UAT 测试报告
- 上线切换方案及应急预案

## 五、关键假设与风险

### 5.1 关键假设

1. **系统访问权限**：奇瑞汽车将在项目启动 2 周内为实施团队提供所有 15+ 系统的沙箱环境和开发账号，不因权限问题延误工期。
2. **内部资源保障**：各业务域数据 Owner 能按评估人天保障配合时间，关键节点（UAT、上线）不因内部人员变动受影响。
3. **历史数据质量**：历史主数据质量状况在一般水平（脏数据比例 ≤ 30%）；若超过 30%，清洗工作量将相应增加。
4. **接口标准统一**：15+ 源头系统和下游系统能够提供标准的 API 或数据库接口，不存在无法对接的黑盒系统。
5. **MDM 平台选型已定**：本评估假设 MDM 平台软件已完成选型并采购，实施团队对所选平台具备熟练经验。
6. **需求相对稳定**：各阶段需求变更控制在 20% 以内；重大需求变更（影响 20% 以上工作量）需走变更管理流程并调整合同。
7. **AI 训练数据可用**：7 大 AI 场景所需历史训练数据可从各业务系统中获取，且经数据 Owner 授权使用。
8. **网络及安全合规**：云 GPU 算力资源使用符合奇瑞汽车信息安全规定，数据不出境限制已明确。

---

### 5.2 投资超支风险因素

1. **需求范围蔓延**：业务部门在实施过程中不断提出新需求，导致工作量持续增加，建议严格实施变更管理（CCB）。
2. **历史数据质量极差**：若历史数据脏数据比例超过 40% 或存在大量无法自动清洗的复杂情况，需增加 1～2 名数据质量工程师，P4 阶段费用可能增加 20～40 万元。
3. **源头系统改造难度超预期**：部分老旧系统（如定制化 MES/CGBOM）可能缺乏接口能力或改造文档，需要更多逆向工程工作，P3 阶段费用可能增加 15～30 万元。
4. **AI 模型精度不达标**：若 7 大场景中某几个 AI 模型因数据质量或算法复杂度导致多轮迭代，P7 阶段工期可能延长 1～2 个月，增加费用 15～25 万元。
5. **接口联调协调难度大**：100+ 条接口涉及多个外部系统供应商，各方联调窗口协调困难，可能导致 P6 阶段工期延误和费用增加。
6. **关键人员流失**：实施过程中外部顾问或内部关键人员（数据 Owner、系统管理员）离职，导致知识断层，重新磨合增加费用。
7. **硬件/云资源价格波动**：AI 计算资源（GPU 云算力）价格波动可能影响 P7 阶段工具费用，建议提前锁定资源合同价格。
8. **上线后稳定期延长**：若上线后系统稳定性问题较多，P6/P9 阶段需延长驻场支持，预计每延长 1 个月约增加 10～15 万元。
